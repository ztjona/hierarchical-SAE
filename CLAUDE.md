# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Where to read what

- **`readme.md`** — project overview, two-headed CNN architecture, experience tuple schema, reward functions, loss approaches, training loop, quick-start commands, project layout. **Read this first.**
- **`Research-status.md`** — *slim* ledger (~120 lines): champion, current open problem, code-version letter index, last few results, forward queue. **Read first when deciding what to run next or interpreting results.**
- **`docs/diary/series-<letter>.md`** — per-series long-form: every experiment in that code-version letter, its hypothesis, fixed params, result, and post-mortem. Linked from `Research-status.md`'s series index. **Consult when reasoning about a specific experiment family.**
- **`docs/diary/<date>_<topic>.md`** — design notes (new schemas, new model classes, new auxiliary losses). Index in `docs/diary/README.md`. **Consult before modifying a `TRANSITION_SCHEMA`, model class, or bot inference rule.**
- **`tools/results_compare.py`** — CLI over the JSONL summaries at `results/<series>/<exp>.summary.jsonl` (`CHECKPOINTS/` stays binary-only). Use `list`, `show <exp>`, `diff <a> <b>`, `rank --metric KEY`. Authoritative source for cross-experiment numbers (the markdown files describe *interpretation*, the JSONL stores *values*).
- **`analysis/` — diagnostic suites (not training; check here before writing any new analysis script to avoid duplicating tooling).** **`analysis/competence_audit/` is the single evaluation suite of record (since 2026-06-08); its `METRICS.md` is the canonical, complete metric-definitions doc — read it before quoting or adding any eval metric.** The suite = `audit.py` (static Tests A–E incl. winning-placement / depth-1 losing-piece-avoidance, with reusable rule helpers `_placing_wins`/`_piece_is_losing`) + `loss_autopsy.py` (game-trajectory autopsy of losses, classifying each loss avoidable-vs-forced; **default opponent is `punishing`** — un-diluted, the champion gate) + `oracle_target_audit.py` (target-vs-fit diagnostic for SELECT failures, comparing `Q_select` argmax to the actual `_minimax_select_target`) + `select_capacity_probe.py` (head-capacity vs trunk-representation diagnostic: frozen-feature read-out probes vs the deployed head — 2026-06-08 verdict: the SELECT wall is representation-limited, a deeper head buys ~1pp) + `select_safety_learnability.py` (trunk *capacity* vs *allocation*: same arch minus the place head, trained scratch + champion-init on depth-1 hot labels — 2026-06-08 verdict: capacity is sufficient, the wall is allocation ⇒ pressure the trunk, don't grow it); all write per-(exp,epoch) JSONL under `competence_audit/results/<exp>/`. **`analysis/qselect_diagnostics/` (D1/D2/D3 — `PLAN.md`, `REPORT.md`, `_common.py`'s shared `load_checkpoint`/`sample_states` loaders) is LEGACY** — retained for provenance; the inline `d1_*` JSONL keys are still emitted but are secondary, not the gate. The select gate of record is the Test-B **hot-give rate** (`METRICS.md`); the autopsy `avoidable_rate` is ~10× opponent-diluted — do not read it as select competence.

Do not restate content from those files here — link to the relevant section instead.

## Operational rules

These are non-obvious contracts that span files or that have already bitten us. They live here because they're load-bearing for code changes, not because they're useful prose for a human reader.

- **Don't reintroduce an adversarial sign flip in the Bellman step while `REWARD_FUNCTION="propagate"`.** The rewards already encode player perspective; double-negation diverges Q as `R/(1−γ)`. See `docs/diary/series-FG.md` → `FA_Bellman` post-mortem.
- **"Q_select saturation" was largely a metric artefact (2026-05-19, D1 diagnostic).** The match-outcome-conditioned Δ in `QuartoRL/results_io.py` (`q_select_winners` / `q_select_losers`) averages over functionally-neutral states and hides per-position structure that Q_select does encode under oracle supervision. **[Superseded 2026-06-08]** the D1 fields (`d1_safe_piece_recall` etc.) are no longer the select-side gate — they are a depth-2 *offline mean* that can rise while in-play behaviour collapses, and the autopsy `avoidable_rate` they were tied to is ~10× opponent-diluted. **The select gate of record is now the `audit.py` Test-B hot-give rate** (`analysis/competence_audit/METRICS.md`). D1 is still useful as a secondary read but is not load-bearing; the Δ is still wrong too. Before treating any "Q_select looks flat" finding as load-bearing, read `analysis/competence_audit/METRICS.md` (and, for the original artefact history, `analysis/qselect_diagnostics/REPORT.md`).
- **Curriculum fine-tuning from N=2 → larger N catastrophically forgets.** Don't assume a gentler LR/TAU will save it — the root cause is replay-buffer distribution shift. See `docs/diary/series-A.md` → `Ac_fineShallow`.
- **The `-1` sentinels in the experience tuple (`action_place=-1` first move, `action_sel=-1` terminal) are load-bearing.** `DQN_training_step` asserts they never co-occur and that `action_sel=-1` implies `done=True`. Don't silently filter them out of the buffer.
- **Place and select are independent action spaces.** Take `max` over each head independently, never over averaged logits (this was the correct half of commit `51b59ba`).
- **`mode_2x2=True` is the default across training and evaluation.** Keep it consistent — a bot trained with 2×2 wins against a no-2×2 baseline isn't a valid comparison.
- **Pickled results may contain CUDA tensors.** Use the `CPUUnpickler` pattern in `tools/view_qv.py` when loading `CHECKPOINTS/<exp>/<exp>.pkl` on a CPU-only machine.
- **`TRANSITION_SCHEMA` is a triplet contract** (schema name × model class × bot class). The valid combinations are documented at the top of `trainRL.py`. `joint` uses `QuartoCNN*` + `Quarto_bot`; `decoupled_autoreg` uses `QuartoCNNAutoreg*` + `Quarto_autoreg_bot`; `unified_autoreg` uses either (`QuartoCNNAutoregUnified*` + `Quarto_unified_bot`) for the OA-series mask-enabled inference, OR (`QuartoCNNUnifiedNoMask` + `Quarto_unified_nomask_bot`) for the QC-series no-mask inference + aux legality head. Mixing a model from one row with a bot/schema from another will silently produce wrong aux semantics — no exception, just bad gradients. The `unified_autoreg` schema reuses the `DQN_training_step_decoupled_autoreg` target machinery, so target rules (`DECOUPLED_TARGET_STYLE`) apply to all autoreg schemas. The QC training loop additionally computes a per-batch `BCEWithLogits` legality loss via `policy_net.legality_logits(state_board, state_aux)` against `legality_target_from_board(state_board)` and adds `λ_legality · L_legality` to `L_DQN` before `backward()`.
- **`USE_MINIMAX_SELECT_TARGET` (T-series) is the single high-level switch** that activates minimax-oracle distillation on Q_select. When True in `trainRL.py`, it (1) overrides `DECOUPLED_TARGET_STYLE` to `td_place_minimax_select`, (2) instantiates a `MinimaxBot` oracle at `MINIMAX_SELECT_DEPTH`, (3) passes it to both `gen_experience` calls, and (4) makes `DQN_training_step_decoupled_autoreg` return a **5-tuple** with a per-piece legality mask on the SELECT side. The training loop branches on `len(dqn_result) == 5` to apply masked SmoothL1 on the full 16-d Q_select vector. With the flag False, all this is a no-op: gen_experience still emits the new `target_sel_minimax*` keys but zero-filled, and the 4-tuple return path is unchanged. Targets are **frozen in the buffer at the moment of state visit** — not recomputed on replay.
- **`COMPUTE_D1_INLINE` (default True) ships D1 metrics into the per-checkpoint JSONL.** When True AND `TRANSITION_SCHEMA == "unified_autoreg"`, `build_checkpoint_record` / `build_final_record` call `compute_position_structure_record` in-process (self-play sampling + minimax-depth-2 oracle + Q_select aggregation) and merge `d1_safe_piece_recall`, `d1_forcing_loss_bottom_recall`, `d1_spearman_rho_mean` (+ accounting fields) into the record. Auto-disabled for non-unified-autoreg schemas (the diagnostic uses `Quarto_unified_bot`). Cost: ~10s per checkpoint at `D1_N_STATES=200`. D1 failures are caught and surfaced as `d1_error` rather than crashing training. Don't rely on D1 fields existing in legacy JSONLs — emission is forward-only.

- **`LAMBDA_HOT` + `QuartoCNNAutoregUnifiedS4Hot` (Y-series) add an auxiliary hot-piece BCE head** that shapes the *trunk* to encode select-safety (the wall is allocation, not capacity — `series-X.md`). The model adds an `fc_hot` head and a `hot_logits()` accessor; `forward()` is unchanged (returns `(q_place, q_select)`), so the triplet stays `unified_autoreg` × `QuartoCNNAutoregUnifiedS4Hot` × `Quarto_unified_bot` and the head is a **training-time scaffold not used at inference**. When `LAMBDA_HOT>0`, `trainRL.py` adds `hot_head_aux_loss` (masked `BCEWithLogits` on SELECT rows vs the frozen `target_hot_piece`, mirroring the QC legality head) to `L_DQN`; `EMIT_HOT_MASK` is now also true when `LAMBDA_HOT>0` so the buffer carries real hot labels. No-op for non-Hot models or `λ=0`. The weighted term is logged as `loss_data["loss_hot_values"]`. **Aux losses inflate the pre-clip grad norm past `MAX_GRAD_NORM=1.0` — that's a loss-scale effect, not a clip bug; balance via λ, never by raising the clip.** See [[aux-loss-scale-vs-grad-clip]].

## Adding a new experiment

- Follow the naming scheme in `Research-status.md` → `Experiment Naming Convention`: first letter bumps on code/algorithm changes, second letter on hyperparameter sweeps within that code version. `run_trains.py` appends the `(<idx>)<MMDD>_<PARAM>_<VALUE>` suffix.
- **Parallel multi-arm sweeps are already thread-capped — don't re-add it.** `run_trains.py` prints a "background, parallel, thread-capped, logged" block that prefixes every arm with `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1` and runs it via `nohup … > logs/<exp>.log 2>&1 &` (then `disown -a`), so N parallel PyTorch processes don't oversubscribe a small-core machine. To launch a sweep across the available cores, just run that emitted block — do **not** add per-run `taskset`/`set_num_threads`/env pinning, and don't keep raising it as a concern.
- When a sweep concludes:
  1. The JSONL summary at `results/<series>/<exp>.summary.jsonl` is written automatically by `trainRL.py`. Backfill older runs with `tools/pkl_to_jsonl.py` (binaries stay under `CHECKPOINTS/<exp>/`; JSONL + plots + per-series notes live under `results/<series>/`).
  2. Append a "Result" subsection to the relevant `docs/diary/series-<letter>.md` (Hypothesis → Fixed params → Decision gate → Result → Conclusion).
  3. Update `Research-status.md` if the result changes the champion, the open problem, or the forward queue. Keep that file under ~150 lines.
