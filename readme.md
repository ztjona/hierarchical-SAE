# Quarto RL — DQN Training Framework

## Overview

This project trains a DQN agent to play [Quarto](https://en.wikipedia.org/wiki/Quarto_(board_game)) via self-play. The game engine is [quartopy](https://github.com/ztjona/Quartopy).

Quarto is a two-player board game on a 4×4 grid with 16 unique pieces (each with 4 binary attributes). A turn has **two decisions**: place the piece your opponent gave you, then select a piece to give your opponent. You win by completing a line (row, column, diagonal, or optionally 2×2 square) of 4 pieces sharing at least one attribute.

Research status and experiment results are tracked in [Research-status.md](Research-status.md).

## Architecture & Key Concepts

### The Two-Headed DQN

The agent uses a **two-headed CNN** (`QuartoCNN_uncoupled` in `models/CNN_uncoupled.py`) that outputs Q-values for both decisions simultaneously:

```
Input: board state (16×4×4 one-hot) + piece to place (16 one-hot)
  │
  ├─ piece_feat: Linear(16→16) + ReLU → reshape to (1×4×4)
  │
  ├─ Concat [board, piece_map] → (17, 4, 4)
  │   Conv1(17→16, 3×3) + ReLU
  │   Conv2(16→32, 3×3) + ReLU
  │   Flatten → FC1(512→128) + ReLU + Dropout(0.5)
  │
  ├── Q_place head: Linear(128→16) + tanh  →  Q-value per board position [-1, 1]
  └── Q_select head: Linear(128→16) + tanh  →  Q-value per piece to give [-1, 1]
```

Both heads share the convolutional backbone but have **independent** final layers (hence "uncoupled"). There is also `CNN1.py` (original coupled version) where Q_select depends on Q_place output.

### Experience Tuple

Each game turn produces one experience tuple (generated by `gen_experience` in `QuartoRL/RL_functions.py`):

| Field | Shape | Description |
|-------|-------|-------------|
| `state_board` | (16, 4, 4) | Board state before action (one-hot: P1 pieces, P2 pieces, empty, invalid) |
| `state_piece` | (16,) | One-hot of the piece received from opponent |
| `action_place` | scalar | Board position [0-15] where piece was placed. **-1 on first move** (empty board) |
| `action_sel` | scalar | Piece index [0-15] given to opponent. **-1 on terminal states** (game ended) |
| `reward` | scalar | Game outcome (depends on reward function) |
| `done` | bool | True only for the terminal state |
| `next_state_board` | (16, 4, 4) | Board after placement |
| `next_state_piece` | (16,) | The piece that was selected (given to opponent) |

**Critical asymmetry:** A turn is a (place, select) pair, except:
- **First move:** `action_place=-1` (player only selects a piece on an empty board)
- **Terminal move:** `action_sel=-1` (game ended after placement, no piece selection)

### Reward Functions

With `REWARD_FUNCTION="propagate"`, the final game result (P1 win → R=+1, P2 win → R=-1, draw → R=0) is assigned to **all** states, alternating sign by player perspective:

```python
reward[i] = R if i % 2 == 0 else -R   # P1 states get +R, P2 states get -R
```

This means the adversarial perspective is **already encoded in the rewards**. The Bellman equation uses the standard `Q(s,a) = R + γ * max Q(s')` without sign flip.

### Loss Approaches

The `LOSS_APPROACH` parameter controls how Q_place and Q_select losses are combined in `DQN_training_step` (in `QuartoRL/RL_functions.py`):

| Approach | Description |
|----------|-------------|
| `combined_avg` | `Q = (Q_place + Q_select) / n_valid`, with target `R + γ*(max_place + max_select)/2`. Single averaged loss. |
| `only_place` | Only trains Q_place head, Q_select zeroed. |
| `only_select` | Only trains Q_select head, Q_place zeroed. |
| `separate_bellman` | Independent Bellman per head: `loss = (L_place + L_select) / 2`. Each head gets its own target. |
| `mc_select` | Q_place uses standard Bellman; Q_select is supervised with the Monte Carlo return `γ^steps_to_terminal * outcome`, avoiding a noisy self-bootstrap through the select head. |

### Training Loop (`trainRL.py`)

Each epoch:
1. **Generate experience:** Self-play with exploration temperature → `n_last_states` turns per game × `MATCHES_PER_EPOCH` games
2. **Extend replay buffer** (keeps last `NUM_EPOCHs_BUFFER` epochs of data)
3. **Train:** Full sweep of buffer in mini-batches. Each step:
   - Sample batch from replay buffer
   - Compute Q-values and Bellman targets via `DQN_training_step`
   - Backprop loss, clip gradients, optimizer step
   - Soft-update target network every `TARGET_UPDATE_FREQ` steps (Polyak with τ)
4. **Evaluate:** Run contests against baselines, track win rates and Q-value distributions
5. **Save:** Checkpoint model and plots every `FREQ_EPOCH_SAVING` epochs

### Experiment Automation (`run_trains.py`)

Generates modified copies of `trainRL.py` for parameter sweeps. Each copy overrides one parameter (e.g., `N_LAST_STATES_INIT`) and gets a unique experiment name. Run them in parallel via `./runpy.sh`.

## Project Structure

```
trainRL.py              # Main training script (all hyperparams at top)
run_trains.py           # Parameter sweep generator
play_between_bots.py    # Head-to-head bot comparison
play_bot.py             # Human vs bot
run_swiss_tournament.py # Tournament evaluation across checkpoints
runpy.sh                # Training launcher with logging

bot/                    # Bot wrappers
  CNN_bot.py            # Quarto_bot: wraps a NN model for game play
  CNN_F_bot.py          # Extended architecture bot
  human.py              # Human player interface
  random_bot.py         # Random baseline

models/                 # Neural network architectures
  NN_abstract.py        # Base class (export_model, load_model)
  CNN_unbound.py        # QuartoCNN_unbound — unbounded Q-values (no tanh), experimental variant
  CNN_uncoupled.py      # QuartoCNN_uncoupled — tanh-bounded Q-values [-1,1]
  CNN1.py               # QuartoCNN — original (Q_select depends on Q_place)
  CNN_fdec.py           # Extended CNN architecture
  CNNfrancis.py         # Francis architecture variant

QuartoRL/               # RL core functions
  RL_functions.py       # gen_experience(), DQN_training_step(), convert_2_state_action_reward()
  contest.py            # run_contest(), contest_2_win_rate()
  plotting.py           # plot_win_rate(), plot_loss()
  observers.py          # plot_boards_comp(), plot_Qv_progress()

tools/                  # Analysis utilities
  compare_training.py   # Compare training curves across experiments
  view_qv.py            # Visualize Q-value distributions over training

CHECKPOINTS/            # Saved models organized by experiment name
analysis/               # Experiment analysis notebooks
logs/                   # Training logs (auto-generated by runpy.sh)
train_scripts/          # Auto-generated training scripts (from run_trains.py)

Research-status.md      # Experiment results and current research status
```

## Quick Start

### Requirements
- Python 3.x
- [quartopy](https://github.com/ztjona/Quartopy) v1.3.2+
- PyTorch, TorchRL, tqdm, colorama, docopt
- See `requirements.txt`

### Running Training
```bash
# Single run
./runpy.sh trainRL.py

# Parameter sweep
python run_trains.py          # generates train_scripts/*.py
# then run the printed commands

# Models saved to CHECKPOINTS/<EXPERIMENT_NAME>/
# Logs saved to logs/
```

### Evaluating
```bash
# Head-to-head
python play_between_bots.py

# Swiss tournament across checkpoints
python run_swiss_tournament.py CHECKPOINTS/<experiment>/ --rounds=200

# Compare training curves
python tools/compare_training.py <experiment_name> <N_runs>

# View Q-value evolution
python tools/view_qv.py <experiment_name> <N_runs>
```

### Playing Against the Bot
```bash
python play_bot.py
```
